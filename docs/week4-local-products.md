# 로컬 실습용 시드 생성

## 실행 방법

로컬 MySQL과 상품 조회 서버를 실행해 테이블이 생성된 상태에서, 저장소 루트의 다른 터미널에서 실행한다.

```bash
./gradlew :apps:commerce-api:seedLocalProducts
```

생성된 브랜드 ID와 조회 URL은 `apps/commerce-api/build/local-product-seed-result.json`에서 확인한다.

명령을 다시 실행하면 같은 구성의 새 데이터가 추가된다. 한 번의 실습에는 한 번만 실행한다. 기본 로컬 설정으로 서버를 재시작하면 테이블이 초기화되므로, 시드를 유지하며 재시작할 때는 아래 명령을 사용한다.

```bash
./gradlew :apps:commerce-api:bootRun --args='--spring.jpa.hibernate.ddl-auto=validate'
```

## 생성되는 데이터

| 종류 | 구성 |
| --- | --- |
| 브랜드 | 2개 (`week4-seed-brand-1`, `week4-seed-brand-2`) |
| 상품 | 총 10,000개, 브랜드마다 5,000개 |
| 상품 이름 | 영문 소문자 5~30자 |
| 가격 | 1,000·5,000·10,000·30,000·50,000·100,000원 |
| 재고 | 상품마다 0~100개 |
| 사용자 | 좋아요에 사용할 신규 사용자 4명 |
| 좋아요 | 총 308건. 브랜드마다 첫 100개 상품에 0~4개씩 배정하고 나머지는 0개 |
| 상품 생성 시각 | 브랜드별로 2026-10-01·2026-10-02 00:00 (한국 시간) |

고정 난수 시드 `20261012`를 기준으로 같은 상품 내용을 다시 생성한다. DB의 실제 ID는 실행마다 달라진다. 같은 가격·좋아요 수와 인기 상품을 포함하는 실습 자료이며 실제 서비스의 데이터 분포를 대표하지 않는다.
